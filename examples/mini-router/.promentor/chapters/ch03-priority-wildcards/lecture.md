# 优先级与通配符

这个 Chapter 学的是路由冲突时「谁该赢」，以及如何用 `*path` 吃掉剩余路径。这是路由器里最容易写错、也最能体现设计的一层。

它在系统中的位置：动态匹配不再返回「第一个能对上的」，而是返回**最具体**的那条。

## 冲突是常态

同时注册：

```text
GET /users/new
GET /users/:id
```

请求 `GET /users/new` 两条都能解释：前者是字面量 `new`，后者把 `new` 当成 id。

如果「先注册先赢」，结果取决于添加顺序，API 会在你改注册顺序时悄悄换人。规则必须和顺序无关：**静态段 > 参数段 > 通配符**。

## Specificity，不是 if/else 补丁

不要写：

```python
if path == "/users/new":
    ...
elif looks_like_id(path):
    ...
```

每多一条特殊路径就多一个分支。原始设计给模板打分：

| 段类型 | 分数 |
|--------|------|
| 静态 `users` | 4 |
| 参数 `:id` | 2 |
| 通配 `*path` | 1 |

`/users/new` 得 8，`/users/:id` 得 6。分高的赢。同分时保留先扫到的即可——测试不依赖注册顺序之外的平局策略。

静态表仍然先查。`/users/new` 若作为静态路由注册，根本不会进入打分循环。这是第 1 章那次「静态命中立刻返回」的真正用途。

## 通配符吃剩余段

`/files/*path` 对 `/files/a/b/c` 应得到 `{"path": "a/b/c"}`。

`*` 必须出现在模板末尾才有意义：它的语义是「从这里到请求结束」。实现上，遇到 `*` 就把 `request[index:]` join 起来，然后立刻返回，不再要求段数相等。

`/users/:id` 对 `/users/42` 应打败 `/users/*rest`：参数比通配更具体。

## Lab 要实现什么

在第 2 章能力之上：

- `/users/new`（静态）赢过 `/users/:id`
- `/users/:id` 赢过 `/users/*rest`
- `/files/*path` 捕获多段
- 静态、参数、method 不匹配的旧行为保持不变
