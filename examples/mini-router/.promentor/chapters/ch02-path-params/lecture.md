# 路径参数：规则不是字面量

这个 Chapter 学的是：路由段里的 `:id` 不是字符串，是一条捕获规则。静态表的 `==` 在这里会失效。

它在系统中的位置：静态查找 miss 之后，路由器必须用「模式」去解释请求路径，并抽出参数交给 handler。

## 为什么整串比较不够

你已经能匹配 `/users`。现在要匹配 `/users/42`、`/users/7`，而且让 handler 拿到 `{"id": "42"}`。

如果继续用 dict key：

```text
("GET", "/users/42") → show_user
```

每个用户 id 都得先注册一遍。路由表描述的是**规则**，不是已经出现过的 URL。

## Segment，不是整条 path

把路径切开：

```text
pattern:  /users/:id   →  ["users", ":id"]
request:  /users/42    →  ["users", "42"]
```

逐段看：

- `users` 与 `users`：字面相等，继续
- `:id` 与 `42`：这是规则。不要 `==`，把 `id=42` 记进 params

段数对不上（`/users/42/extra`）就是未匹配。嵌套同理：`/users/:uid/posts/:pid` 对 `[users, 1, posts, 9]`。

## 两种表仍然要分开

`:id` 出现后，有人会把所有路由都改成线性扫描。不要。

- 没有 `:` / `*` 的，继续进静态 dict
- 有模式的，进动态表，存的是 **segment 列表**，不是原始字符串

查找顺序：先静态，再动态。`/users` 这种精确路径不该为了参数功能变慢。

## 常见错法

把 `:id` 和 `42` 做 `==`。测试会告诉你 `params` 是空的——因为比较根本没成功，或者成功了但你没捕获。

`:id` 的含义是：这一段**任意值都接受**，并且把值记下来。

## Lab 要实现什么

`add_route` / `find_route` 同时支持：

- 静态路径（第 1 章的行为必须还在）
- `/users/:id` → params `{"id": "42"}`
- `/users/:uid/posts/:pid` → 两个参数
- 段数不对或 method 不对 → `(None, {})`

通配符 `*path` 和下章的优先级先不用做。
